# VLESS + REALITY VPN — будущий план

Реализовано и задеплоено (v0.0.3): VLESS over TCP, REALITY-сервер с зеркалированием
dest в хендшейке, xtls-rprx-vision с direct copy, Python-тулинг (`vpnctl`, `link2xray`),
деплой (`deploy/`, `docs/deploy-ubuntu.md`). История — в git-тегах `v0.0.1`–`v0.0.3`.

Runbook эксплуатации: [deploy-ubuntu.md](deploy-ubuntu.md).

## Дальше

- [ ] **Обновить прод-VPS до v0.0.3**: `git pull`, rebuild, restart; перевыписать ссылки
      с `&flow=xtls-rprx-vision` (`vpnctl init` — добавить флаг/дефолт).
- [ ] **`vpnctl rotate-sid`**: плавная ротация short_id одной командой
      (добавить sid → напечатать ссылки → по флагу убрать старый).
- [ ] **Скрипт подбора dest-кандидатов**: критерии — TLS 1.3 + HTTP/2, не заблокирован в РФ,
      крупный популярный домен, низкий RTT от VPS; держать 2–3 запасных в `server_names`.
- [ ] **UDP ASSOCIATE** (2-байтовый length-prefix на пакет) — по необходимости.
- [ ] **Метрики** (счётчики соединений/трафика в журнал) — по необходимости.
- [ ] **M3 — свой клиент (опционально):** SOCKS5 → VLESS+REALITY, uTLS chrome fingerprint.

## Анти-рекомендации (не делать)

Свой домен в SNI (блокируемая метка для DPI), порт ≠ 443 (443 и есть маскировка),
обфускация поверх REALITY, CDN+WS (план «C» при регулярных банах IP).
Операционно: репутация IP/хостера и план переезда важнее протокольных мер —
на практике убивают баны ASN, а не анализ трафика.
